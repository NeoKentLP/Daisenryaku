# 第一部分：核心规则 (Core Rules)

## 第一章 基础概念

### 1.1 三层架构

```
兵种模板(UnitType) ──→ 部队(Squad) ──→ 成员(Member)
   编制定义              战场实体            个体HP+武器
```

- 部队占一格，一格一部队
- 成员不独立行动，部队统一行动
- 编制由 UnitType模板 固定，创建时确定，不可战场动态拆分/合并

### 1.2 成员类型（5种）

| 类型 | ID | 行为 | armor范围 |
|------|-----|------|----------|
| 步兵 | `infantry` | 徒步、CQB可用、可驻建筑、有士气 | 0 |
| 载具 | `vehicle` | 轮/履带移动、禁CQB、无方向装甲 | 1~15 |
| 火炮 | `artillery` | 牵引、间瞄规则、禁CQB | 1~5 |
| 空中 | `air` | 飞行、需燃料、机场起降（直升机免机场） | 0~8 |
| 支援 | `support` | 运输/补给/工兵，无战力或极弱 | 0~3 |

- 分类原则：**看行为（怎么移动、怎么作战），不看武器**
- 后期导弹类（ATGM/SAM/MLRS）→ 不新增类型，用高PEN值体现

### 1.3 伤害模型 — PEN穿透判定

```
武器: base_damage, penetration (PEN)
目标: armor

判定:
  PEN >= armor → 穿透 → 全额伤害 × 波动 × cover减伤 × 士气修正
  PEN < armor  → 未穿透 → 仅压制效果，伤害固定=1
```

- 隐蔽(concealment) 影响命中端
- 掩护(cover) 影响伤害端
- 载具不拆乘员：一辆坦克 = 1个载具成员，HP=车体耐久

### 1.4 地图与尺度

| 标准 | 20×14 hex (280格) |
|------|-------------------|
| 扩展 | 全局变量控制，支持关卡自定义大小 |

### 1.5 回合与AP

| 参数 | 值 |
|------|-----|
| AP/回合 | **3** |
| 移动消耗 | 1AP = 1次移动，移动距离=移动力 |
| 攻击消耗 | 2AP |
| 突击消耗 | 3AP |
| 警戒消耗 | 1AP |
| 自由组合 | 移动/攻击不互斥，互相消耗AP |

### 1.6 回合流程

每个回合按以下阶段顺序执行，阶段内不可穿插其他阶段操作：

```
己方回合:
  [阶段1·回合开始]  条件增援部署→压制恢复判定(先判定门槛后恢复)→
                     溃败timer-1→士气恢复+5→CD-1→重置AP为3→重置反应次数
  [阶段2·行动阶段]  玩家依次操作各部队（移动/攻击/警戒/固守/补给等）
                     顺序不限，移动/攻击自由组合
  [阶段3·回合结束]  触发"回合末"效果：标记已行动→清理临时标记(炮兵暴露等)→
                     传递回合给对手

AI回合:
  [阶段1-3] 同己方回合，AI自动执行
```

**首次回合先手判定**:
- 进攻型任务（全灭/突破/摧毁）→ 攻方先手
- 防守型任务（坚守/护送）→ 守方先手
- 占领任务 → 双方各掷d100(BS修正)，高者先手

**关键时序规则**:
- 反应（警戒/反击/ZOC借机）在敌方行动阶段**即时触发**，中断当前操作，结算完恢复
- "回合末"效果统一在阶段3结算：清理顺序为压制门槛判定→士气恢复→溃败timer→清理标记
- 增援部队在阶段1部署，部署后本回合**不可行动**（AP保留，下回合可用）

### 1.7 成员与部队消亡

**成员死亡**:
- 成员HP归零即**死亡**，不可在战斗中复活
- 死亡成员从部队列表中移除，其武器/装备消失
- 医疗资源**不可复活死兵**，仅用于战后恢复未归零的伤兵

**部队消灭**:
- 部队所有成员死亡 → 部队被消灭
- 消灭瞬间触发：歼灭者士气+10、相邻友军士气-10、经验获取判定
- 部队被消灭后其ZOC消失、归属格重新变为无归属

**部分存活**:
- 部队中部分成员死亡不影响剩余成员的行动能力
- 聚合属性(armor/vision)按存活成员重新计算
- 指挥官自动转入康复状态，战斗结束后回到指挥官池

### 2.1 防御属性

#### 回避 / 隐蔽

| 属性 | 适用 | 公式作用 |
|------|------|---------|
| evasion 回避 | 载具、空中 | 命中率 减去 evasion |
| concealment 隐蔽 | 步兵、火炮、支援 | 命中率 减去 concealment（基础值+地形加成） |

| Squad接口 | 方式 |
|-----------|------|
| `get_move_type()` | 由当前状态决定（上车=载具类型，下车=foot） |
| `get_vision_range()` | max(所有成员 vision_range) |
| `get_armor()` | max(所有存活成员 armor) |
| `has_flag(flag)` | any(成员有该标记) |

### 2.5 主动性（Initiative）

部队层属性，决定常规攻击中谁先开火。不影响CQB(同时开火)和反应次数系统。

```
主动性 = 兵种模板基础值 + 等级修正(精锐+1/王牌+2) + 指挥官被动 - 机动姿态惩罚(载具机动姿态时-1)
```

| 兵种模板参考值 | 主动性 |
|-------------|--------|
| 侦察车 | 8 |
| 战斗机 | 10 |
| 坦克 | 6 |
| 步兵 | 4 |
| 火炮 | 2 |
| 轰炸机 | 2 |

**常规攻击**: 攻方主动性 > 守方 → 攻方先开火；攻方 < 守方 → 守方先开火；相等 → 攻方先开火。
**ZOC脱离**: 高主动性移动方 → 脱离ZOC前执行突围射击（消耗1弹药）。若打死ZOC来源 → 不触发借机攻击；未打死 → 正常触发。

## 第三章 移动阶段

### 3.1 移动动作

| 规则 | 值 |
|------|-----|
| 1AP = 1次移动 | 移动距离 = 移动力 |
| 移动力 | 步兵2 / 履带3 / 轮式4 / 飞行6 |
| 燃料消耗 | 1次移动 = 1燃料（所有地面载具 + 空中单位） |
| 燃料耗尽 | 地面=无法移动；空中=下回合坠毁；IFV可下车（步兵走） |
| 卡车无燃料 | 上车后无法移动，下车变回徒步 |

### 3.2 双层地形架构

```
hex = 基础地形(1个必选) + 结构层(0~N个可选)

查询规则:
  移动消耗 = min(各结构修正, 基础地形消耗)
  cover    = max(基础地形cover, 各结构cover)
  CQB      = OR(任一是CQB)
  归属权    = OR(任一是归属格)
```

#### cover 减伤体系

`cover值 × 5% = 减伤%`, 硬上限70%。

| cover值 | 减伤 | 示例 |
|---------|------|------|
| 0 | 0% | plain/desert/road/bridge/minefield/water |
| 1 | 5% | swamp/snow/village/airfield |
| 2 | 10% | hills/forest/trench |
| 3 | 15% | mountain/city/factory/ruins |
| 4 | 20% | bunker |

#### 载具掩体自动切换

载具停在cover格: cover≤1(≤5%)=机动(evasion正常); cover≥2(≥10%)=防御(evasion=0, cover生效)。载具享受所有cover，享受时evasion=0。

#### 建筑摧毁

命中次数制(非HP积数)。工兵爆破即毁。重炮(A级)每发=2次命中。

| 结构 | 命中次数 | 摧毁后 |
|------|---------|--------|
| trench | 3 | 移除 |
| bridge | 6 | 移除，恢复河道 |
| village | 9 | → ruins |
| city | 15 | → ruins |
| factory | 15 | → ruins |
| bunker | 20 | 移除 |
| airfield | 不可破坏 | — |

### 4.4 攻击流程

```
① 选己方部队 → 选目标 → 确定
② 弹出战斗预览面板: 武器选择+命中率预览（按4.4.1公式实时计算）
③ 确认攻击 → resolve_combat():
     遍历部队每把选定武器，每发独立判定:
       4.4.1 命中判定
       → 命中则随机分配目标成员（等概率）
       → 4.4.2 穿透判定（PEN vs armor）
       → 4.4.3 伤害计算
     → 汇总展示(每类型武器命中×发/伤×点)
④ 反击结算(单独日志)
```

#### 4.4.1 完整命中公式

```

最终命中率 = clamp(
      攻击方基础BS
    + 成员等级BS修正
    + 武器.bs_bonus
    + 士气命中修正
    + CQB命中修正
    + 兵种技能修正
    - 目标防御值(evasion 或 concealment)
    - 压制命中减损
    - 天气命中减损
    - 距离减损
  , 5%, 95%)
```

**逐项解释**:

| 项 | 来源 | 意义与取值 |
|----|------|-----------|
| **攻击方基础BS** | 成员属性 | 基础命中技能。步兵默认60（即60%），载具成员独立设定。这是命中的起点 |
| **成员等级BS修正** | §10.1等级表 | 新兵+3、老兵+8、精锐+15、王牌+25（百分比加算） |
| **武器.bs_bonus** | 武器属性 | 武器自身的精度修正。狙击枪高正值(+10~+20)，重机枪低负值(-5~0) |
| **士气命中修正** | §7.1士气状态 | 狂热+15 / 高昂+10 / 正常0 / 混乱-10 / 溃败不可攻击 |
| **CQB命中修正** | §4.5 CQB评级 | 仅在CQB地形且使用cqb武器时生效。3→+15, 2→+5, 1→-10, 0→不可用 |
| **兵种技能修正** | §11.5具体技能 | 精确射击/火力压制等主动技能的临时命中加成，数值由技能定义 |
| **目标防御值** | 目标属性 | 二选一：载具/空中用**evasion**（机动规避）；步兵/火炮/支援用**concealment**（隐蔽），直接减法。cover不影响命中端，只影响伤害端 |
| **压制命中减损** | 攻击方压制值 | 压制>50时额外-5，压制>80时额外-10。表示被压制时射击精度下降 |
| **天气命中减损** | §17.1 | 雨天-5%，暴风雨-10%，雾天-10%，雪天无命中减损 |
| **距离减损** | 射程等级 | C(0hex)=0, M(1hex)=0, L(2hex)=-5, L(3hex)=-10, A(4hex)=-15, A(5hex)=-20。超出武器range_max不可攻击 |
| **clamp(5%,95%)** | 硬上限 | 最终命中率不低于5%（保底）且不超过95%（杜绝必中），攻守对称 |

**例**: 一个老兵步兵(BS=60+8=68)用G43步枪(bs_bonus=0)射击2hex外(距离-5)的森林中的敌方步兵(conceal=2)，士气正常(0)非CQB(0)无技能(0)无压制(0)晴天(0)：
```
68 + 0 + 0 + 0 + 0 + 0 - 2 - 0 - 0 - 5 = 61%
clamp(61%, 5%, 95%) = 61%
```

**成员分配**: 每发子弹独立对目标部队的存活成员随机分配（等概率），一发子弹只打一个人。

#### 4.4.2 穿透判定

```
diff = 武器PEN - 目标armor

穿透概率:
  diff ≥ +3 → 100% 穿透
  diff = +2 → 90%  穿透
  diff = +1 → 70%  穿透
  diff =  0 → 50%  穿透
  diff = -1 → 20%  穿透
  diff = -2 → 5%   穿透
  diff ≤ -3 → 0%   穿透

判定: roll d100 ≤ 概率 → 穿透 → 进入4.4.3伤害计算
      否则 → 未穿透 → 伤害固定=1，仅产生压制值(武器.suppression)
```

#### 4.4.3 伤害计算

```
if 穿透:
    最终伤害 = 武器.base_damage
        × 伤害波动(1 + rand(波动下限%, 波动上限%))
        × (1 - min(目标.cover值 × 5%, 70%))   // cover减伤，上限70%
        × 士气伤害修正(狂热×1.1，其他×1.0)
    最终伤害 = round(最终伤害)

    同时产生压制值 = 武器.suppression（受目标压制抵抗A减损）
```

- 武器选择UI: 攻击前弹出汇总面板，按类型汇总显示(步枪×6 弹药30)，默认全选，可取消特定武器节省弹药
- 每次开火消耗武器弹药1发（weapon.ammo -= 1），弹药归零不可开火

### 4.5 火炮间瞄规则

- 仅攻击**己方视线内**的目标格
- 开火**暴露自身位置**(敌方反炮可反击)，暴露即时生效，回合末消失
- 侦察兵专属技能"炮火引导"待部队等级解锁
- 打击建筑按命中次数制

## 第五章 近战阶段 (CQB)

### 5.1 CQB结算流程

攻方选目标(必须在CQB地形)→弹出战斗预览面板→攻方手动选武器→守方自动全选cqb_rating≥1武器→双方同时独立结算→消灭守方=攻方占领敌格。

### 5.2 武器过滤

CQB结算中仅 `member_type==infantry` 且 `cqb_rating≥1` 的成员武器参战。载具成员武器跳过。

### 5.3 突击代价与结果

AP=3。失败（守方未灭）=攻方留在原地。成功=占领敌格。主动性不影响CQB。命中/伤害公式与常规攻击共用。

## 第八章 战场环境

### 8.1 视野与战争迷雾

#### 迷雾三态

| 状态 | 地形 | 敌军 | 建筑变化 |
|------|------|------|---------|
| **未探索** | ❌ 全黑 | ❌ | ❌ |
| **已探索/无视野** | ✅ 灰色调 | ❌ | ❌ 不更新(需重新侦察) |
| **可见** | ✅ 正常 | ✅ | ✅ 实时更新 |

实现: 覆盖式fog_overlay层，Polygon2D per hex。

#### 视线检测

Bresenham hex线算法。阻挡: forest + mountain阻挡视线。山地双向规则(A能看到B↔B能看到A)。A在mountain上 → 忽略forest阻挡(仅mountain可挡)。

#### 已探索区地形变化

不自动更新(城市→废墟/新建战壕/布雷等需重新侦察才可见)。

### 8.2 ZOC 控制区

- 部队对其6相邻格施加ZOC
- 敌进入ZOC → **立即停止移动**
- 敌在ZOC内 → 命中-10、己方回合末+5压制
- 敌离开ZOC → 3AP(包围时)、触发借机攻击(1反应+弹药)

### 8.3 包围效果

每相邻友军 = -1敌军计数。净数决定状态：

| 相邻敌净数 | 状态 | 效果 |
|---------|------|------|
| 1-2 | ZOC | 进入即停、命中-10、+5压制/回合 |
| **3-4** | **包围** | 脱离ZOC=3AP、命中-10、+10压制/回合 |
| **5-6** | **完全包围** | 脱离ZOC=3AP、**cover减伤百分比减半**、+10压制/回合、**士气-10/回合** |

### 8.4 压制系统

#### 压制值定义

范围: 0-100

**来源**:

| 来源 | 压制增量 |
|------|---------|
| 被攻击 | `武器.suppression × 命中次数`, 受抵抗A减损 |
| ZOC | +5/回合 |
| 包围(3-4敌) | +10/回合 |
| 完全包围(5-6敌) | +10/回合 |

**恢复**: 回合末 +20(基础)。先判定门槛, 后恢复。

#### 压制门槛

| 条件 | 效果 |
|------|------|
| 0-30 | 无影响 |
| **>30** | **伤害波动下移生效** |
| >50 | 士气-5/回合 + 反应-1 |
| >60 | 禁用主动技能 (重整例外) |
| 士气=溃败(0) | 压制=100, 不恢复 |
| 士气<30 | 压制恢复减半(10/回合) |
| **压制=100** | **移动力减半+反应-1+全主动技能禁用(重整例外)+伤害波动最大下移** |

#### 伤害波动公式

```
有效压制 = 压制值 - 30

下限 = -20% - (有效压制 × 0.2%)
上限 = +20% - (有效压制 × 0.5%)

随机伤害 = base_damage × (1 + rand(下限%, 上限%))
```

例 压制=50: 下限=-24%, 上限=+10% → 伤害 76%-110%

#### 压制抵抗 (A+D)

**A（减损）** — 受击时生效: `实际压制增量 = 原始增量 × (100% - A%)`

**D（效果减免）** — 伤害波动计算时生效: 先对原始压制值应用D抵抗，再减30得有效值。

**掩体减损**: `实际压制增量 × (100% - cover值 × 2%)`

两者同时生效。

| 等级 | 压制抵抗(A+D) |
|------|-------------|
| 乌合之众 | 0% |
| 新兵 | 10% |
| 老兵 | 20% |
| 精锐 | 35% |
| 王牌 | 50% |

### 一、攻击发起阶段

#### 动作选择（先行于目标选择）

attack 和 assault 是 §9 中的独立 SkillDef，玩家**先选动作类型，再选目标**：

```
底部操作栏:
  [射击 2AP]  → 常规攻击, 全部武器可用
  [突击 3AP]  → CQB突击, 仅 infantry + cqb_rating≥1, CQB地形才可见
  [待机]      → 结束该部队行动
```

- 突击按钮仅在**CQB地形且目标相邻**时激活
- 非常规攻击的动作（射击/突击/待机）是一次性选择，互斥

#### 目标选择与预览

```
玩家操作:
  ① 选中己方已激活部队(AP>0)
  ② 点击动作按钮([射击] 或 [突击])
  ③ 点击目标敌方部队(需满足该动作的射程/武器条件)
  ④ 弹出战斗预览面板(只显示该动作的预览):
      左: 武器列表(按类型分组, 可取消特定组省弹药)
          射击: 全部可用武器, 灰色=弹药0或射程外
          突击: 自动过滤为 infantry + cqb_rating≥1
      右: 预期命中率 / 伤害范围 / 压制值 / 反击预期
      底: [确认] [取消]
  ⑤ 确认 → AP扣除 → 进入战斗执行
```

**边界检查**:
- 目标是否在武器 range_min~range_max 内 → 否=不可选(灰色)
- 是否触发警戒范围(§6.2) → 是=预览附加"触发警戒"标注
- 弹药0的武器类型 → 灰色禁用

### 二、常规攻击执行序列

```
resolve_fire(firer, target, weapon_types):
  // 单方向火力投送子流程, 返回 target 是否仍有存活成员
  // weapon_types: 参与射击的 weapon.type 字符串列表
  //   常规攻击 = firer.selected_types (玩家选定的武器类型, 如 ["rifle"])
  //   反击/警戒 = firer.all_types   (所有可用武器类型, 自动全选)
  squad_suppression = 0

  for each weapon_type in weapon_types:
    for each member in firer.members:
      // 找该成员持有的、属于本 weapon_type 的第一把可用武器
      weapon = member.get_first_weapon_of_type(weapon_type)
      if weapon == null: continue(下一member)

      [1] 弹药检查
        weapon.ammo > 0 → 消耗1发, 继续
        ammo=0 → 跳过该member

      [2] 射程检查
        distance ≤ weapon.range_max → 继续
        distance < weapon.range_min → 跳过

      [3] 命中判定(§4.4.1)
        roll d100 ≤ final_hit_rate → 命中 → [4]
        → 未命中, 下一member

      [4] 目标成员分配
        if target.members 为空: break ALL  // 无人可打, 终止全部循环
        t = random(target.members, 等概率)

      [5] 穿透判定(§4.4.2)
        diff = weapon.PEN - t.armor
        | diff  | 穿透率 |
        |-------+--------|
        | ≥ +3  | 100%   |
        | +2    | 90%    |
        | +1    | 70%    |
        | 0     | 50%    |
        | -1    | 20%    |
        | -2    | 5%     |
        | ≤ -3  | 0%     |
        roll d100 ≤ 穿透率 → 穿透 → [6]
        未穿透 → damage=1, 仅累积压制 → [7]

      [6] 伤害计算(§4.4.3)
        dmg = weapon.base_damage × (1±波动%) × (1-cover×5%) × 士气修正
        dmg = round(dmg)

      [7] 伤害应用
        t.HP -= dmg
        squad_suppression += weapon.suppression  // 累积至部队级

      [8] 成员死亡检查(§1.7)
        if t.HP ≤ 0:
          t 标记死亡, 从 target.members 移除
          firer.morale += 2
          日志: "[weapon.name] 击杀 [t.role]"
          if target.members 已空: break ALL  // 灭队, 终止全部循环

      [9] 弹药归零
        if weapon.ammo == 0: 标记为耗尽

  target.suppression = min(target.suppression + squad_suppression, 100)
  return target.members.size() > 0
```

```
resolve_combat(attacker, target, selected_types):
  // selected_types: 玩家选定的 weapon.type 列表, 如 ["rifle","mg"]

  // ===== 0. 主动性比较 (决定谁先开火) =====
  // 概率制: 每点主动性差±10%, clamp(10%, 90%)
  initiative_diff = attacker.initiative - target.initiative
  attacker_first_pct = clamp(50 + initiative_diff * 10, 10, 90)
  if roll d100 ≤ attacker_first_pct:
    first = attacker, second = target
  else:
    first = target, second = attacker

  // ===== 1. 第一轮 (first 射击 second) =====
  // AP消耗在此处扣除(2AP)
  second_alive = resolve_fire(first, second, first.selected_types)

  // ===== 2. 第二轮 (second 反击, 条件: 存活 + 距离≤1 + 有反应) =====
  // 反击使用全部可用武器类型, 射程+1(§6.2支援规则)
  if second_alive and 双方距离 ≤ 1 and second.士气 ≥ 正常 and second.剩余反应 > 0:
    resolve_fire(second, first, second.all_types)
    second.剩余反应 -= 1

  // ===== 3. 警戒反应检查 =====
  // 目标已死则跳过(无意义的警戒)
  if target.members 非空:
    for each 警戒敌军 in target.周围警戒友军(§6.2):
      resolve_fire(警戒敌军, target, 警戒敌军.all_types)
      // 警戒射击不消耗反应次数(§6.2 免费反应), 仅消耗弹药(在resolve_fire内)
      if target.members 已空: break

  // ===== 4. 士气连锁(§7.2) =====
  // 双方都可能在本轮交锋中被灭(反击/警戒反杀)
  if first.members.size() == 0:
    second.morale += 10
    first 标记消灭, 清除ZOC/警戒
    相邻格敌军 morale -= 10
  if second.members.size() == 0:
    first.morale += 10
    second 标记消灭, 清除ZOC/警戒
    相邻格敌军 morale -= 10

  // ===== 5. 士气状态更新(§7.1) =====
  双方各自更新:
    士气≤0→溃败  1-20→混乱  21-70→正常  71-90→高昂  91-100→狂热
    (单向向下调整, 不跳跃回正常以上)

  // ===== 6. 胜利条件检查(见第六节) =====
  check_victory_condition()

  // ===== 7. 战斗结果展示(见第七节) =====
  显示战斗日志面板
```

### 三、CQB突击执行序列

与常规攻击的区别：

| 差异项 | 常规攻击 | CQB突击 |
|--------|---------|---------|
| AP消耗 | 2 | 3 |
| 武器限制 | 全部可用 | 仅 infantry成员 + cqb_rating≥1 |
| 载具武器 | 可用 | 跳过 |
| 开火时序 | 攻击方先 → 守方反击 | **双方同时结算** |
| 成功奖励 | 无 | 守方灭队 → 攻击方占领目标格 |
| 自锁 | 无 | consumes_all_ap |

```
resolve_combat_cqb(attacker, target):
  // CQB专用: 与§9 SkillDef assault指令的条件一致
  // resolve_fire 内部需额外过滤: 仅 infantry成员 + cqb_rating≥1 的武器参战
  // 命中时使用CQB命中修正(§4.6), cover正常计算

  // Step 1: 提取双方可用的 weapon.type 列表(仅cqb合格类型)
  // resolve_fire 在循环中会逐成员检查武器.cqb_rating
  attacker_types = attacker.get_cqb_types()   // 如 ["smg","rifle"]
  defender_types = target.get_cqb_types()

  // Step 2: 双方同时射击(各自调用 resolve_fire)
  // 注意: 同时意味着双方的伤亡不影响对方的射击结果
  // AP消耗在此处扣除(3AP), 自锁 consumes_all_ap
  attacker_alive = resolve_fire(attacker, target, attacker_types)
  defender_alive = resolve_fire(target, attacker, defender_types)

  // Step 3: 压制汇总 + 士气连锁(同§二第4-5阶段)
  // CQB不触发反击/警戒(已在同时结算中覆盖)

  // Step 4: 胜负判定
  if not defender_alive:
    attacker 占领 target格
    attacker.morale += 15   // 占领归属格
    攻击方移动至目标格
  elif not attacker_alive:
    attacker 被反杀, 部队消灭, 留在原地
  else:
    攻击方留在原地

  // Step 5: 胜利条件检查(见第六节)
  // Step 6: 战斗结果展示(见第七节, 双方并列显示)
```

### 四、反应系统触发时序

反应触发规则是对称的，不区分己方回合/敌方回合——谁在行动，对方就反应。

**行动方的三种操作各自触发：**

```
行动方执行移动:
  → 每进入一个新hex, 检查:
    - ZOC检测: 新hex在对方ZOC内且对方有借机机会 → ZOC借机攻击(§6.3)
    - 防空检测: 空中单位且在防空警戒范围 → 防空射击
    - 地雷检测: hex有地雷 → 地雷伤害

行动方执行攻击(常规/CQB):
  → 结算到§二·第3阶段(警戒反应检查):
    - 目标本身满足反击条件(距离≤1, 士气≥正常, 有反应次数) → 反击
    - 目标相邻友军处于"支援警戒" → 支援射击
       (反击在resolve_combat中已处理, 这里处理支援侧的额外射击)

行动方执行火炮间瞄开火:
  → 对方火炮处于"反炮警戒"且射程覆盖 → 反炮反击
```

**中断规则**:

```
- 反应中断当前操作 → 执行完整战斗结算(同§二流程, 角色互换)
- 反应结算完成 → 恢复被中断的操作
- 多反应同时触发 → 按 ZOC借机 > 反击 > 支援 > 反炮 > 防空 优先级依次结算
- 同一部队同一回合总反应次数 ≤ 该部队反应次数上限(§6.1)
```

### 五、士气连锁完整规则

士气变化**严格按执行顺序依次累积**，而非汇总后一次性调整：

```
攻击执行中的士气变化:
  逐发命中 → 击杀士气(+2/成员) → 即时更新
  全部命中结算完成后:
    - 整队消灭 → +10(额外)
    - 整队消灭 → 相邻格友军 -10

变化后即时检查士气状态(§7.1):
  可能发生: 正常→高昂(击杀敌人后士气超过71)
  也可能: 高昂→正常(友军被灭导致士气从85降至75)
  士气在战斗中持续动态变化

攻击目标被灭后的连锁:
  ① target标记为"已消灭"
  ② 清除target的ZOC/警戒
  ③ 调用check_victory_condition()
  ④ 若战斗未结束, 攻击方可继续执行其他部队操作
```

**灭队判定**: 部队.members.length == 0 → 灭队 → 从战场移除 → 进入胜利检查。

### 六、胜利条件检查

#### 检查时机

| 时机 | 触发条件 |
|------|---------|
| 每次攻击结算完成后 | 目标灭队 OR 攻击方发现目标已无存活部队 |
| 每回合末 | 检查所有胜利条件 |
| 固定规则触发 | 如护送单位抵达撤离点等 |

#### 条件判断

```
check_victory_condition():
  for each condition in mission.victory_conditions:
    match condition.type:
      "全灭敌军":
        if 敌方无存活部队 → 胜利
      "占领据点":
        if 己方占领所有指定据点格 → 胜利
      "坚守阵地":
        if 己方回合数 ≥ mission.hold_turns → 胜利
      "突破防线":
        if 己方任意部队到达指定区域 → 胜利
      "摧毁目标":
        if 指定目标HP≤0 → 胜利
      "护送撤离":
        if 被护送单位到达撤离点 → 胜利

  if any condition met:
    进入胜利结算(战后展示面板)
  else:
    继续游戏
```

#### 失败条件

| 条件 | 触发 |
|------|------|
| 己方全灭 | 检查同上，己方无存活部队 → 失败 |
| 坚守目标被占 | 坚守任务中，目标据点被占 → 失败 |
| 护送单位被灭 | 护送任务中，护送目标死亡 → 失败 |

### 11.12 升级备选池

#### 11.12.1 技能等级规则

| 规则 | 说明 |
|------|------|
| **等级不增AP** | 技能升级时，AP消耗**绝不可增加**（Lv1→Lv2→Lv3必须≤原AP） |
| **等级可减AP** | 特定技能升级后可减少AP消耗（如某技能Lv1=2AP, Lv2可降至1AP） |
| | 减少AP的配置在JSON `levels[].ap_cost` 字段单独设置 |
| | 开发实现时，需校验：`levels[1].ap_cost ≤ levels[0].ap_cost`，依此类推 |
| **等级提升效果** | 数值型技能：效果值按档位递增（固定增量或等比） |
| | 机制型技能：Lv1 only，不可升级 |
| | 效果不随等级提升而改变作用域或影响范围 |

#### 11.12.2 初始化技能分配

指挥官创建时技能分配规则：

| 来源 | 数量 | 规则 |
|------|------|------|
| **背景技能** | 固定1个 | 由背景模板决定，仅创建时分配，**不进入升级备选池** |
| **天赋技能** | 固定1个 | 初始化等级随机(Lv1 60% / Lv2 30% / Lv3 10%)，不可跳级 |
| | | 天赋升级出现概率30%，见§11.4 |
| **品质技能** | 0~3个 | 按稀有度概率获得：菜鸟50%×0 / 预备军官30%×1 / 老兵15%×2 / 英雄5%×3 |
| | | 从通用池随机抽取，不包含兵种专属和背景技能 |

#### 11.12.3 升级备选池（每次升级3选1）

指挥官每升一级，从3个备选中选择1个。备选池生成规则：

| 槽位 | 来源 | 规则 |
|------|------|------|
| **槽1** | **兵种专属** | 固定：从当前指挥官指挥的部队种类对应的兵种技能库抽1个 |
| | | 如步兵指挥官→从 `infantry` 分支抽；载具→从 `vehicle` 分支抽 |
| | | 若该兵种技能已全部学完且已达最高级 → 改为从通用池抽 |
| **槽2&3** | **通用池 + 升级选项** | 详见下方生成流程 |

**槽2&3生成流程**：

```
① 判断是否出现升级选项（20%概率）
   是 → 从已有技能中选1个其Lv1→Lv2或Lv2→Lv3(且未达最高级)
        该升级选项占用槽2或槽3（随机选1个位置）
   否 → 跳过

② 剩余空槽从通用池随机抽取：
   - 排除初始化已分配的技能(背景/天赋/品质不再出现)
   - 排除已学满级的技能
   - 按所有剩余技能的数量比例随机
   - 兵种专属技能仅当指挥官背景匹配时才可能出现在通用池中
   - 槽2&3中最多1个被升级选项占用
```

#### 11.12.4 等级门槛

| 规则 | 说明 |
|------|------|
| **Lv1→Lv2** | 只有当指挥官已学会某技能Lv1时，该技能的Lv2才可能出现在升级选项中 |
| **Lv2→Lv3** | 只有当指挥官已学会某技能Lv2时，该技能的Lv3才可能出现在升级选项中 |
| **天赋例外** | 天赋技能初始化时随机分配Lv1-Lv3（§11.4），不需要从Lv1逐级升 |
| **unlock_level** | 技能配置中`unlock_level`字段表示该技能首次出现的指挥官最低等级 |
| | 如钢墙铁壁 unlock_level=2 → 指挥官Lv2后才可能见到 |

### 11.13 康复时间

指挥官所在部队被消灭后，指挥官进入 **recovering**（康复）状态，经过一定回合数后方可重新任命。

**康复时间规则**：

| 规则 | 说明 |
|------|------|
| **触发条件** | 指挥官所在部队被消灭 → 状态变为 `recovering` |
| **康复期内** | 不可任命到任何部队，不可出现在招募池 |
| **康复结束** | 状态变回 `idle`，可重新任命 |
| **最小值** | 至少1回合 |

**基础康复时间**（按指挥官等级）：

| 指挥官等级 | 基础康复时间（回合） |
|-----------|-------------------|
| Lv1-3 | 3 |
| Lv4-6 | 4 |
| Lv7-9 | 5 |
| Lv10 | 6 |

**营房时间减免**（参见§22.2 指挥官营房）：

| 营房等级 | 减免 |
|---------|------|
| Lv4 | -1回合 |
| Lv7 | -2回合 |
| Lv10 | -3回合 |

**公式**：`最终康复时间 = max(基础时间 - 营房减免, 1)`

# 第三部分：特殊规则 (Special Rules)

## 第十四章 空中单位

### 14.1 移动规则

- **飞行移动**：无视所有地形消耗(=1)。不可停在mountain/river格
- **航程** = 移动力 × 燃料剩余量（每1AP移动消耗1燃料）
- **到达己方机场**：燃料消耗停止（回合末不扣燃料），安全，不坠毁
- **燃料耗尽**（燃料=0且不在机场）：下回合开始坠毁
- 固定翼**只能回机场格**补充燃料

### 14.2 基本行为

| 行为 | AP | 说明 |
|------|-----|------|
| 移动 | 1AP/动作 | 飞行无视地形 |
| 对空攻击 | 2AP | 使用 anti_air=true 武器 |
| 对地攻击 | 2AP | 使用地面目标武器 |
| 待机 | 0AP | |
| 补给(机场相邻) | 1AP | 燃料+弹药回满，仅己方机场 |
| **对地支援(警戒)** | 1AP | 激活后不可主动移动/攻击。敌地面部队入射程→免费反应 |
| **制空巡逻(警戒)** | 1AP | 同上，触敌空中单位→免费反应 |

空中单位不适用上下车、固守、突击。

### 14.3 空对空战斗

使用同一战斗公式(命中→穿透→伤害)，无额外机制。

### 14.4 防空

敌方防空警戒：hex走格子式触发。飞行器每经过一个hex→防空检查→被拦截。

### 14.5 空降/空投

B流程: 空降兵+运输机同机场→登机(1AP)→运输机手飞→空降(剩余AP全耗)→本回合不能动。CD=2。防空拦截=运输机被击落→空降兵全灭。空投补给同理。

### 14.6 空中与地面同层

空中与地面同格（C方案）。飞行器与地面部队在同一hex分层存在（空中层/地面层），不互斥。

## 第十五章 后勤与资源

### 15.1 四种独立资源

| 资源 | 基准价(二战) | 消耗场景 |
|------|------------|---------|
| 弹药 (Ammo) | 2 | 补给时消耗：恢复武器弹药消耗全局弹药池 |
| 燃料 (Fuel) | 5 | 载具移动 |
| 备件 (Spare Parts) | 3 | 载具维修、建造 |
| 医疗用品 (Medical) | 1 | 治疗伤兵 |

4种独立资源共用资源仓库容量池。不可负值。

### 15.2 弹药消耗与补给链

**弹药层级**:
```
全局弹药资源池(仓库) → 部队补给动作 → 武器.ammo(单兵弹药)
```

**开火消耗**:
- 每次开火：`武器.ammo -= 1`
- 武器.ammo 归零 → 该武器不可使用，需要补给恢复

**补给消耗**:
- 补给动作(1AP)将部队所有武器的弹药恢复至 max_ammo
- 消耗全局弹药 = `Σ[(max_ammo - current_ammo) × supply_cost]` 遍历部队所有武器
- 全局弹药不足时：补给失败，消耗0，武器弹药不变（提示资源不足）
- 战后自动补给同样消耗全局弹药池

### 15.3 消耗时机

| 资源 | 消耗时机 | 说明 |
|------|---------|------|
| 弹药 | 补给时消耗全局池 | 武器开火消耗武器.ammo，补给时从全局池补充 |
| 燃料 | 每1AP移动动作 | 消耗1燃料/动作, 空中每回合自动消耗 |
| 备件 | 工兵维修/建造 + 战后基地修理 | |
| 医疗 | 战后自动恢复(医疗站) + 战场急救技能施放 | |

上下车**不消耗燃料**。

### 15.4 补给体系

**补给源**: HQ(相邻)、补给部队(相邻)、机场(仅固定翼补燃料)

**补给规则**: 部队在补给源相邻格 → 花1AP → 弹药+燃料回满。固定翼仅可在己方机场补燃料。

**补给部队**: 支援系编制(有HP/无战力/可被攻击)。被消灭后补给功能失效。

**指挥官应急补给**: 同时+2燃料&+2弹药, CD5回合。

### 15.5 战后自动补给

战斗胜利后: 所有存活部队的弹药+燃料自动回满(消耗全局资源池)。无需在补给源附近。

### 15.6 暂搁置

- 补给线功能（补给路径阻断判定）
- 补给部队的补给站建造
- 治疗/维修的详细消耗公式

### 17.2 天气变化机制

#### 17.2.1 回合流程位置

```
[阶段1·回合开始]
  ① 预报更新（生成下回合预报）
  ② 天气变化判定（实际天气可能改变）
  ③ 若新天气含禁飞 → 处理紧急降落
  ④ 条件增援部署 → 压制恢复判定 → ...
```

#### 17.2.2 预报系统

每回合开始时生成**下回合的预报天气**，显示在UI右上角：

| 规则 | 值 |
|------|-----|
| 预报内容 | 下回合的**天气类型** |
| 准确率 | **80%**（20%概率实际≠预报） |
| 预报生成时机 | 本回合[阶段1]开始时 |
| 玩家可见 | 当前天气图标 + 预报天气图标（带"预报"标识） |

**预报判定**:
```
预报天气 = 按§17.2.3 概率表选新天气  // 与天气变化同机制
实际天气 = 预报天气 (80%概率)
         ≠ 预报天气 (20%概率 → 重新roll表选实际天气)
```

预报让玩家可以**前瞻规划**（如：预报明天暴风雨→空军今天赶紧出击/地面部队提前过河），但20%的不确定性保留战术意外。

#### 17.2.3 变化概率

| 参数 | 默认值 | 说明 |
|------|--------|------|
| 天气变化概率 | **25%** | 每回合roll d100 ≤ 此值 → 触发天气变化判定 |
| 新天气选择 | 查概率表 | 从下表按权重选新天气，结果=当前天气则"天气持续" |

#### 17.2.4 天气概率表（默认权重）

| 天气 | 权重 | 概率 | 备注 |
|------|------|------|------|
| 晴 | 35 | **35%** | 基础天气 |
| 雨 | 25 | **25%** | 多云转雨 |
| 暴风雨 | 10 | **10%** | 恶劣天气，较少出现 |
| 雪 | 15 | **15%** | 可经关卡配置设为0%（夏季战场） |
| 雾 | 15 | **15%** | 晨雾/辐射雾 |

**变化流程**:
```
回合开始 →
  roll d100:
    ≤ 25%: 触发变化 → roll d100 按概率表选新天气
           → 新天气 = 当前? 视觉不变 : 切换到新天气(瞬切)
    > 25%: 天气持续，不变
```

**期望行为**:
- 平均天气持续时间：约 4-5 回合
- 晴占战场总时间约 35%，雨占 25%，其余各占 10-15%

#### 17.2.5 禁飞处理

当天气变为含"禁飞"的状态时：

| 单位状态 | 处理 |
|---------|------|
| 已在地面 | 本回合不可激活 |
| 正在空中 | **强制指令**：向最近可着陆位置移动。若回合末仍在空中→**坠毁** |
| 固定翼着陆 | 需己方airfield格 |
| 直升机着陆 | 非障碍地形格(Mountain/River/Lake除外) |

### 17.4 地面累积状态（核心新机制）

> 参考装甲军团：持续天气改变地面物理状态。雨→泥泞，雪→积雪。
> 地面状态是**全图的统一状态**（非逐格计算），在回合末更新，下回合生效。

#### 17.4.1 计数器系统

每回合末根据当前天气更新全局计数器：

| 当前天气 | 泥泞计数器变化 | 积雪计数器变化 |
|---------|---------------|---------------|
| **晴** | -1（最低0） | -1（最低0） |
| **雨** | **+1** | 0 |
| **暴风雨** | **+2** | 0 |
| **雪** | 0 | **+1** |
| **雾** | 0 | 0 |

#### 17.4.2 状态转换

| 状态 | 触发条件 | 解除条件 |
|------|---------|---------|
| **正常** | 初始 | — |
| **泥泞** | 泥泞计数器 ≥ **3** | 泥泞计数器降至 **0** |
| **积雪** | 积雪计数器 ≥ **2** | 积雪计数器降至 **0** |

**状态互斥**: 泥泞和积雪不同时存在。积雪计数器>0时泥泞计数器不增加（雪覆盖一切）；两者同时达标时积雪胜出。

**变化时机**: 仅发生在**回合末**，下回合[阶段1]开始生效。

**例**:
```
回合1: 雨 → 回合末 泥泞=1
回合2: 雨 → 回合末 泥泞=2
回合3: 暴风雨 → 回合末 泥泞=4 → 下回合开始"泥泞"
回合4: 晴 → 回合末 泥泞=3(仍≥3) → 泥泞持续
回合5: 晴 → 回合末 泥泞=2(<3) → 但≠0, 仍泥泞
回合6: 晴 → 回合末 泥泞=1(≠0) → 仍泥泞
回合7: 晴 → 回合末 泥泞=0 → 解除泥泞
```

#### 17.4.3 泥泞效果

| 效果 | 值 |
|------|-----|
| **移动** | 全类型+1MP/格，轮式额外+1MP/格（即轮式共+2） |
| **河流** | **不可通行**（桥梁除外） |
| **燃料消耗** | 地面载具每次移动额外+1燃料 |
| **视野** | 无额外影响 |

**与即时天气叠加**: 泥泞移动惩罚 + 当日天气的即时移动惩罚（如有）。

**例**: 雨中泥泞，轮式走plain:
```
即时: 雨→轮式+1          // §17.1
泥泞: 全+1, 轮式额外+1   // §17.4.3
合计: 1(plain) + 1(雨) + 2(泥泞) = 4MP/格
轮式MP=4 ⇒ 最多移1格
```

#### 17.4.4 积雪效果

| 效果 | 值 |
|------|-----|
| **移动** | 轮式+2MP/格，履带+1MP/格，步兵+1MP/格 |
| **河流** | **可通行**（冰面冻结），通行消耗=plain=1MP/格 |
| **燃料消耗** | 地面载具每次移动额外+1燃料 |
| **视野** | 无额外影响（即时天气的视野修正已覆盖雪天） |

**积雪的战略反转**: 原本阻碍移动的河流（需绕道或桥梁通过）在积雪下变成可通行的冰面——雪天不再是单纯的惩罚，而是创造新的进攻路线。

**河流冰面通行规则**: 仅限积雪状态下生效。桥面仍可用。冰面不可建任何结构。

#### 17.4.5 地面状态与天气的独立性

地面状态**不随天气瞬切消失**：

| 场景 | 结果 |
|------|------|

## 第十八章 AI行为框架

> 敌方（及友方自动单位）的决策系统，每回合按固定流水线执行。
> 核心原则：**可解释性优先**——每个决策都可以追溯到一个具体的数值原因。
> 不搞行为树/机器学习，用数值驱动的硬编码流水线。

---

### 18.1 AI回合总流程

```
回合开始(同玩家§1.6 阶段1) →
  for each AI unit (按主动性从高到低排序):
    ① 态势评估: 收集周围威胁/目标/位置
    ② 目标选择: 按威胁分排序选出目标
    ③ 动作选择: 按优先级匹配最佳动作
    ④ 路径规划: A* → 绕ZOC → 执行移动
    ⑤ 执行攻击/警戒/其他
```

**执行顺序按主动性排序**，主动性高的 AI 部队先行动（模拟精锐部队反应更快）。

---

### 18.2 态势评估

每支 AI 部队在每个回合开始时扫描以下数据：

| 数据 | 来源 | 用途 |
|------|------|------|
| 可攻击目标列表 | 武器射程内 + 存活 | 输出选项 |
| 每个目标的反击预期 | 反击伤害公式 | 评估攻击代价 |
| 每个目标的威胁分 | 见 §18.3 | 确定优先级 |
| 周围警戒敌军 | §6.2 | 移动风险 |
| 可移动到的安全格 | 规避已知敌军射程 | 撤退/走位 |
| 可占归属格列表 | 地图上的未占领归属格 | 占领任务走位目标 |
| 目标归属格价值 | 该格在胜利条件中的权重 | 防守/进攻优先级 |

**发现的敌军分两级**：
- **可见敌军**：当前视野内的，可直接攻击
- **已知敌军**：已探索但无视野的，不可直接攻击但计入走位回避

---

### 18.3 威胁评估

每个敌方目标计算一个综合威胁分，AI 优先攻击威胁最高的目标。

```
threat_score(target):
  基础伤害 = estimate_damage_from(target, self)
  击杀概率 = estimate_kill_prob(target, self)

  threat = 0
  threat += 基础伤害 × 1.0          // 打人疼的威胁高
  threat += 击杀概率 × 20           // 能杀我的优先处理
  threat += target.压制值 × 0.1     // 压制高的也烦人
  threat += 反装甲惩罚  × 5         // 对装甲车同理, 下同
  threat += 防空惩罚     × 3

  return threat
```

**取值表**：

| 项 | 条件 | 值 |
|----|------|-----|
| 基础伤害 | 对方能对我造成的期望伤害 | 取伤害范围中值 |
| 击杀概率 | 对方击杀我当前最低HP成员的概率 | 0~1 小数 |
| 压制惩罚 | 对方压制值 > 50 | +5 |
| 反装甲惩罚 | 对方武器.PEN ≥ 己方.armor − 1 | +5/每档 |
| 防空惩罚 | 己方是空中单位且对方有AA | +8 |
| 指挥官惩罚 | 对方有指挥官 | +3 |
| 近距惩罚 | 对方在相邻格 | +5 |

**简化版（简单难度）**：只取基础伤害项，忽略其他。

---

### 18.4 目标选择

```
candidates = 态势评估.可攻击目标
candidates.sort_by(threat_score, descending)

if candidates 非空:
  if 存在 candidates[i] 的 击杀概率 > 0.7:
    首选 = candidates[i]    // 能秒就秒
  else:
    首选 = candidates[0]    // 打威胁最高的

  if 首选的反击可能杀死己方(己方HP低):
    检查是否有次选目标且次选无反击风险
    有 → 攻次选  |  无 → 攻首选(承受反击)
```

**不攻击条件**：

| 条件 | 行为 |
|------|------|
| 己方弹药=0 | 不可攻击 |
| 己方士气=溃败 | 不可攻击，执行溃败撤退 |
| 己方士气=混乱 | 不可攻击 |
| 命中率 < 10% | 不值得打，跳过 |
| 预期伤害 < 目标总HP 5% | 挠痒，跳过 |

---

### 18.5 动作选择

按以下优先级依次尝试，第一个可行的即选中：

```
[1] 突击 | 条件: CQB地形 + 相邻 + 击杀概率 > 0.5 + AP≥3
[2] 攻击 | 条件: 首选目标在射程内 + AP≥2
[3] 警戒 | 条件: AP≥1 + 不在警戒中 + 前方有敌军接近可能
[4] 急行军 | 条件: AP≥1 + 远程目标在2回合可到达位置 + 移动消耗全部剩余AP
[5] 移动(进攻) | 条件: AP≥1 + 朝目标缩短距离 + 仅消耗1AP(保留攻击能力)
[6] 固守 | 条件: 在全掩护地形(cover≥3: 城市/战壕/堡垒/废墟) + 无目标
[7] 移动(撤退) | 条件: 己方HP<30% + 有安全格可退
[8] 待机 | 保底
```

**动作可行性检查**：

| 动作 | 额外条件 |
|------|---------|
| 突击 | 目标不在反击范围？(突击无反) → 更优先 |
| 攻击 | 若反击伤害 > 己方当前HP → 重新考虑 |
| 警戒 | 周围无友军重叠警戒范围 |
| 急行军 | 目标格无已知敌军射程覆盖 + 消耗全部剩余AP(不可再攻击) |
| 移动(进攻) | 目标格无已知敌军射程覆盖 + 消耗1AP(到达后仍可攻击) |

---

### 18.6 路径规划

```
find_path(start, goal, unit):

  // 基础: A* 寻路
  path = astar(start, goal, unit.move_type)

  // ZOC规避: 经过敌方ZOC格需额外检查
  for each hex in path:
    if hex 在敌方ZOC内:
      if unit.主动性 > ZOC来源.主动性:
        // 突围射击 → 继续走(消耗弹药)
      else:
        // 被借机攻击 → 评估是否值得
        if 预期借机伤害 > unit.HP × 0.3:
          path = reroute(hex)  // 绕路

  // 火力覆盖规避: 不经过已知敌军的最佳射程格
  for each hex in path:
    if hex 在已知敌军的射程中心区域:
      path = reroute(hex)
      if path == null:
        // 无安全路径可选 → 走原始路径(承受火力)
        path = astar(start, goal, unit.move_type)

  return path
```

**移动后检查**：
- 若移动后进入某敌军射程 → 自动触发该敌军的警戒/反击（由§6处理）
- 若移动后仍可攻击同一目标（王牌AP=4可移→打）→ 回到 §18.5 继续

### 18.7 集火与配合

**集火条件**（困难难度启用）：

```
1. 多支AI部队的目标列表中，同一目标排名均为前2
2. 其中至少1支部队对该目标的击杀概率 > 0.3
3. 集火目标完成后，其余AI重新评估
```

**实现**（顺序执行框架内）：
```
// AI 部队按顺序逐个行动
// 当某AI执行攻击后, 后续AI重新评估发现同一目标已被选中 → 自动补刀

for each AI unit in sequence:
  if unit.首选目标 == 前一支AI的首选目标:
    if 前一支AI 打残了但未消灭目标:
      unit.首选目标 = 同一目标          // 补刀优先
      unit.目标优先级 += 10              // 提高执行意愿
```

AI 无法提前知道玩家意图，集火只在**执行过程中动态形成**——前面的AI先打，后面的AI看到残血自动补刀。

**配合规则**：
- 前一支AI部队如果打残一个目标但未消灭，下一支AI部队**仅在自身无更高威胁目标时**补刀
- 若补刀目标的威胁分 < 自身原本目标威胁分 × 0.7 → 放弃补刀（防止被集火牵制）
- 若补刀者被反击的风险低于前一支 → 补刀优先

### 18.8 难度差异化

| 难度 | 威胁评估 | 反击考虑 | 集火 | 警戒使用 | 先手概率作弊 |
|------|---------|---------|------|---------|------------|
| **简单** | 仅基础伤害 | 不看 | 不集火 | 少用(30%概率) | — |
| **普通** | 完整公式 | 伤害>当前HP时放弃 | 不集火 | 正常(60%) | — |
| **困难** | 完整公式 | 伤害>当前HP×0.5时放弃 | 启用 | 正常(80%) | 先手率+10%封顶 |
| **极难** | 完整公式+预判2回合 | 伤害>当前HP×0.3时放弃 | 启用 | 全部(100%) | 先手率+15%封顶 |

**作弊规则说明**：
- 困难/极难 AI 在主动性的概率公式中获得固定加成（非绝对先手，只是概率倾斜）
- AI 不获得额外属性/HP/伤害——作弊只在决策层

### 18.9 警戒与反应行为

AI 在己方回合选择警戒后，在玩家回合触发反应时的行为：

| 触发类型 | AI决策 |
|---------|--------|
| 反击(§6.3) | 固定强制执行，消耗1反应+1弹药 |
| ZOC借机 | 固定强制执行，消耗1反应+1弹药 |
| 支援警戒 | 判断能否击杀(击杀概率>0.3) → 执行(免费反应，仅弹药) |
| 防空警戒 | 强制执行(免费反应，仅弹药) |
| 反炮警戒 | 强制执行(免费反应，仅弹药) |

**AI不会在反应上消耗弹药耗尽后无法反击**——弹药≤1时不执行反应（保底留1发以备关键反击）。

| 单位类型 | 行为倾向 |
|---------|---------|
| 步兵 | 偏好CQB地形，优先占建筑 |
| 载具 | 避开CQB(除非突击)，保持距离输出 |

| 防空 | 站在己方部队格间距≤2的区域内(密集区=3格内≥2支友军)，被动掩护 |

### 18.11 极限情况处理

| 情况 | AI行为 | 优先级 |
|------|--------|--------|
| 达成胜利条件在即(本回合可完成) | 所有部队全速冲向胜利目标，无视其他 | **最高** |
| 被包围无路可退 | 拼死攻击(无视反击代价) | 高 |
| 弹药耗尽 | 朝补给部队移动或固守 | 中 |
| 全军只剩最后一支部队且距胜利>1回合 | 优先保命撤退，不主动进攻 | 低 |
| 全军只剩最后一支部队但本回合可胜 | 按"胜利在即"规则，全速冲刺 | — |
| 指挥官阵亡 | 无特殊影响(指挥官不在战场) | — |

**冲突规则**: 按上表从上到下匹配，第一个命中条件的生效。例如：最后一支部队且本回合能赢→走"胜利在即"。

## 第二十一章 部署阶段

### 20.1 部署流程

```
Step 1: 出征选择
  基地 → 点击任务 → 出战名额(任务规定) → 从兵营选部队 → 指定指挥官
  → 编成操作(可选, 调用编成界面) → 确认 → 剩余未部署部队=增援池

Step 2: 战场部署
  ① 放置HQ(HQ视野=4) → 部署区 = HQ周围4格半径
  ② 地面部队部署在HQ相邻格(地面层)
  ③ 空中单位(空中层):
      - 直升机 → HQ上空可部署
      - 固定翼(战斗机/轰炸机/运输机) → 仅当HQ周围4格内有己方airfield时可部署
  ④ 确认 → 进入战斗
  ⑤ 可回退到Step 1重选部队(未确认前)

Step 3: 条件增援(每回合己方回合始)
  增援池来源: Step 1选中的未部署部队
  增援不消耗货币/AP
  部署位置限制: 必须在HQ周围4格范围内
  可增援类型:
     - 地面部队 → HQ相邻格
     - 固定翼 → HQ周围4格内的己方airfield
     - 工兵建造机场完成(3AP+备件+3回合) → 机场在HQ周围4格内 → 可从增援池部署固定翼
```

### 20.2 部署规则

| 规则 | 值 |
|------|-----|
| 部署区范围 | HQ周围**4格半径**（含HQ格） |
| HQ视野 | 4 |
| 无部署时间限制 | ✅ |
| 初始迷雾 | 己方部署区+单位视野内可见，其余按迷雾规则 |
| 敌方部署 | 始终不可见(按难度+任务) |
| 回退机制 | Step 2确认前可回退到Step 1重选 |
| 增援池锁定 | 进入战斗后不可更改增援池 |
