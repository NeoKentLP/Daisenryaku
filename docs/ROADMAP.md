# 开发路线图

> 小步快跑，每步可测试、可验证，逐步实现完整设计。
> 本文档基于 `docs/DESIGN.md`（24章设计规格书）制定。

---

## 现状

**已完成（Phase 1）**：
- Hex网格地图、地形渲染、寻路
- 基础单位、回合管理
- 移动→攻击/待机流程
- 基础AI（就近攻击逻辑）

```
步1 ─→ 步2+3 ─→ 步4+5 ─→ 步8 ─→ 步7+9 ─→ 步10+11 ─→ 步12+13
```

### Phase A — 核心战斗重构

---

#### 步1：三层结构重构

**目标**：从单层Unit改为兵种→部队→成员三层体系

**改动范围**：
| 文件 | 改动 |
|------|------|
| 新增 `scripts/core/squad.gd` | 部队类，管理成员列表、士气、等级、经验 |
| 新增 `scripts/core/member.gd` | 成员类，HP、武器、装备、技能 |
| 重写 `scripts/units/unit.gd` | Squad在战场上的表现（占一格） |
| 重写 `resources/units/unit_data.gd` | 兵种模板：编制结构（各类型成员数量和装备） |
| 更新 `resources/terrain/terrain_data.gd` | 新增地形（沼泽/雪地/废墟/战壕/堡垒） |
| `game_manager.gd` | 部队注册管理 |

**可验证标准**：
- [ ] 地图上显示一支部队占一格
- [ ] 点击部队可查看成员列表（各成员HP/武器/状态）
- [ ] 新地形数据加载正确

**配套测试**：新增 15-20 个烟雾测试用例

---

#### 步2：AP行动点系统

**目标**：统一4AP，替换现有移动+攻击逻辑

**改动范围**：
| 文件 | 改动 |
|------|------|
| `main_controller.gd` | 选中→显示AP消耗→移动(1AP)/攻击(2AP)/待机(0AP) |
| `squad.gd` | 增加`action_points`属性，`spend_ap()`方法 |
| `hex_map.gd` | `get_reachable_hexes`考虑剩余AP |

**可验证标准**：
- [ ] 部队4AP显示在UI上
- [ ] 移动消耗1AP，攻击消耗2AP，待机0AP
- [ ] AP为0时不可移动/攻击
- [ ] AP不足时不可执行对应操作

---

#### 步3：三层战斗公式

**目标**：实现命中→穿透→伤害判定链

**改动范围**：
| 文件 | 改动 |
|------|------|
| 重写 `battle_manager.gd` | 新三层战斗逻辑 |
| 更新武器数据 | 增加伤害类型表、护甲穿透、命中加成、压制力 |
| `member.gd` | 增加方向护甲计算 |

**可验证标准**：
- [ ] 攻击→弹出结果：命中率X%→穿透判定→最终伤害
- [ ] 不同武器对不同成员类型伤害不同
- [ ] 命中随机性：同一组对抗10次，结果有浮动

**配套测试**：新增 20-25 个战斗用例

---

### Phase B — 战术深度

---

#### 步4：士气+压制系统

**目标**：士气状态切换、压制影响伤害波动

**改动范围**：
| 文件 | 改动 |
|------|------|
| `squad.gd` | 士气(0-100)，状态(混乱/正常/高昂/狂热/溃败)，压制(0-100) |
| `battle_manager.gd` | 受攻击→士气↓+压制↑，伤害公式加入压制修正 |
| `ai_controller.gd` | AI考虑士气状态（溃败时撤退） |
| `ui_manager.gd` | 士气/压制显示 |

**可验证标准**：
- [ ] 部队受攻击后士气下降，压制上升
- [ ] 士气<20→混乱（命中惩罚），>90→狂热（伤害加成）
- [ ] 压制>50→伤害波动范围下移
- [ ] 士气0→溃败自动撤退
- [ ] 回合末士气恢复

**配套测试**：新增 10-15 个士气/压制用例

---

#### 步5：ZOC控制区域

**目标**：进入停步、离开双倍AP+借机攻击、ZOC内压制

**改动范围**：
| 文件 | 改动 |
|------|------|
| `hex_map.gd` | ZOC检测：当前部队周围6格是否有敌方 |
| `main_controller.gd` | 移动时检测：进入ZOC→停止，离开→双倍AP |
| `battle_manager.gd` | 借机攻击逻辑 |
| `ai_controller.gd` | AI考虑ZOC |

**可验证标准**：
- [ ] 进入敌方ZOC→立即停止移动
- [ ] 离开ZOC→消耗2AP+触发借机攻击
- [ ] ZOC内→命中惩罚生效

---

#### 步6：CQB+工兵系统

**目标**：突击指令（3AP同时开火）、工兵建造/破坏

**改动范围**：
| 文件 | 改动 |
|------|------|
| `main_controller.gd` | 新增「突击」指令按钮（仅CQB地形显示）|
| `battle_manager.gd` | CQB结算（双方同时开火，武器CQB有效性修正）|
| 新增 `scripts/units/engineer.gd` | 工兵建造逻辑：战壕/地雷/桥梁 |
| `hex_map.gd` | 新增地雷区逻辑(触发→伤害+停止)、可破坏建筑 |

**可验证标准**：
- [ ] 城市/森林/废墟/战壕/堡垒中可选「突击」
- [ ] 突击消耗3AP，双方同时受伤害
- [ ] 冲锋枪在CQB中命中高于步枪
- [ ] 工兵可建战壕(即时)，步兵可建1-2级
- [ ] 踩到地雷区→受伤+停止
- [ ] 城市建筑可被摧毁→变为废墟

## 风险与注意事项

| 风险 | 应对 |
|------|------|
| 步1（三层结构重构）改动最大，可能破坏现有代码 | 先在分支上做，保持烟雾测试通过后再合并 |
| 步3（战斗公式）涉及随机数，测试困难 | 使用固定随机种子或Mock随机数进行测试 |
| 步10-13依赖前面步骤完成，风险累积 | 每步完成后退回主干，不堆积未验证代码 |
| 经济数值未定，影响步7/9/10 | 先用占位数值，后期通过测试调整 |
| 文档与代码同步衰减 | 每完成一步，同步更新`docs/DEVELOPMENT.md`变更记录 |

## 测试策略

```
每步完成时：
  烟雾测试(36例) → 全量测试(102+新增)
  旧用例必须全通过，新用例覆盖本步功能
  全量通过后才算该步完成
```
